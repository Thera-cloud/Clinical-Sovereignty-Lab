Step 3 — GAPS IDENTIFIED
--force-recreate / compose volume churn: explicit prohibition + pre/post data inventory (Vault paths, bind-mount roots) before any recreate.
Ad-hoc SSH deploys: require wrapper script or checklist step; ban “mystery one-liner” deploys not in repo docs.
Vault / critical data guards: mandatory object count or size checksum before/after deploy touching containers with persistent mounts.
GREEN revision discipline: after scp or pull, verify git rev-parse HEAD vs origin/main (or tagged release) for code paths that must match git.
Server working tree: rule for untracked/merge-blocking state on GREEN before git pull.
Completion claims: extend GAP 12 (or sibling rule) to deploy artifact (e.g. server confirms digest) and smoke/E2E for features touched — not only git hash.
Identifier contract: single cross-surface rule: which ID (hardware_id, username, UUID) at bridge, REST, Redis, PG, Flutter for Sensitive Bridge and similar features.
Sensitive Bridge product gating: explicit rollout semantics (universal vs cohort); link to playbook + enforce in code review checklist.
Scope control: approval gate when proposed diff exceeds agreed file/scope list.
EFF fabrication: automated eff_audit / watcher as required (today largely aspirational in prose).
Vault backup cron: heartbeat + alert pattern (stale timestamp = page-on-call), analogous to other agent heartbeat rules.
Dashboard/renderer contracts: JSONL/path schema + renderer sync for conversation review (SkyEye/command surfaces).
