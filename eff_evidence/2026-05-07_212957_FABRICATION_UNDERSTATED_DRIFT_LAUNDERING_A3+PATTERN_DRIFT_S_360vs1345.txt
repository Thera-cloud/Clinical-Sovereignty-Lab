Integration Plan (revised)
The spec's pattern of "replace with generate_therapeutic_response" causes regression of streaming TTFT, ODPE routing, garble retry, AQ bypass. Recommend a wrapper pattern that achieves the same therapeutic effect without replacing the LLM dispatch:

Two integration points (not one)
1. prepare_therapeutic_context() — pre-flight, called BEFORE the LLM branch chain Inputs: user_text, user_id, db_pool, base_system_prompt, conversation_context Outputs: {enriched_system_prompt, max_tokens, audit_metadata} Does:

PART 1 multi-signal autonomic state (text patterns + brevity-shift + TMC class + ec_current)
PART 2 recurring-pattern detection (TMC RECURRENCE + crystal repeat-domain count)
PART 3 mismatch-opportunity assessment
PART 4 context assembly (recent_narratives, neuroscience-domain recall when meta-marker, recent_messages already present)
PART 5 token cap (override _len_cap)
PART 6 system-prompt composition (DNA + state guidance + register guidance + bridge-sentence requirement + anti-repetition + neuroscience crystals if meta)
2. audit_therapeutic_response() — post-flight, called AFTER full_response is final (after AQ bypass) Inputs: full_response, audit_metadata, user_id, db_pool, recent_narratives Outputs: {audit_passed, violations, response_to_send} Does:

PART 8 therapeutic post-audit (WARM register, bridge sentence, somatic invitation, banned phrases, length cap, anti-repetition phrase overlap)
One regenerate retry via chat_completion_with_fallback if violations and mismatch_attempted (NOT a streaming retry — short non-stream regenerate is acceptable on the slow path)
Log to sse_therapeutic_audit_log
PART 9 reconsolidation event candidate (insert CEEEvent row when mismatch_delivered)
