4) Database truth: most coaches have zero published slots
Production query:

Recurring (non-blocked) rows: 4 total.
Per coach: only CoachN / COACH_COACHN_ID has 4 rows; every other coach in the table has 0.
So even with a perfect WebSocket, a client whose assigned coach is not the one with those four rows will correctly see no availability until coaches publish hours in the system that backs coach_availability (see bridge handler using table coach_availability — not the old JSON file path in sessions.py).
