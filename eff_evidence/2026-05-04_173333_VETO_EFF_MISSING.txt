FIX 1 — Google Calendar sync: hardware_id → username resolution
═══════════════════════════════════════════════════════════════

File: backend/app/services/google_calendar_session_sync.py
Function: sync_session_for_participants (lines 313-321)

Problem: function receives hardware_id values (COACH_COACHN_ID, CLIENT_PAULA182_ID)
but google_calendar_connection.user_id stores users.username (per migration 183).
Result: _get_connection returns None, sync is silent no-op.

Required change:
1. Add helper: async def _hardware_id_to_username(pool, hardware_id: str) -> Optional[str]
   - Query: SELECT username FROM users WHERE hardware_id = $1 LIMIT 1
   - Cache result in module-level dict (TTL 300 seconds) to avoid repeat queries
   - Return None if not found, log a warning
2. In sync_session_for_participants:
   - Before the "for uid in (coach_id, client_id)" loop, resolve each ID via _hardware_id_to_username
   - Pass the resolved username (not hardware_id) to sync_session_to_google
   - If resolution fails, log and skip that participant (do not block the other)
3. Add logger.warning if either resolution fails so silent no-ops surface

FIX 2 — Email/SMS notification timezone (UTC → recipient TZ)
═══════════════════════════════════════════════════════════════

File: backend/app/routers/sessions.py
Function: _send_session_link (lines 518-539 area)

Problem: time formatted as "%I:%M %p UTC", template hardcoded timezone="UTC"
Recipients see UTC labels, not their actual timezone.

Required change:
1. Read recipient timezone from users.profile_data->>'timezone' (default "America/New_York" if NULL)
2. Convert datetime to recipient timezone using zoneinfo.ZoneInfo
3. Format as "%I:%M %p %Z" (will display "EST", "PST", etc. naturally)
4. Pass actual timezone string to send_coaching_confirmation timezone= parameter
5. Apply same logic to SMS body construction

Implementation pattern:
   from zoneinfo import ZoneInfo
   tz_name = recipient_profile.get("timezone") or "America/New_York"
   tz = ZoneInfo(tz_name)
   dt_local = dt.astimezone(tz)
   time_str = dt_local.strftime("%I:%M %p %Z").lstrip("0")
   # Pass tz_name to send_coaching_confirmation

Constraints:
- Maximum 25 lines added
- Apply to both client AND coach notification paths
- Handle ZoneInfoNotFoundError gracefully (fall back to UTC with logged warning)
